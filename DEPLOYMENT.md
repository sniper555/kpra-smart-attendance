# Public HTTPS hosting

This file is the Render + Netlify path. Local Docker stays in `docs/DEPLOYMENT.md`. Nothing in this file is a password or an API token.

The public site and the API are on different hosts. The browser calls the API directly. Session cookies are `SameSite=None` and `Secure`, and the API only accepts the site origins you list. On this computer, leave `NEXT_PUBLIC_API_URL` empty and `COOKIE_SAMESITE=lax`. The Next server keeps proxying `/api` to `http://127.0.0.1:8010`.

Render’s free web service sleeps after 15 minutes with no traffic. The first open after that takes about a minute. A free Render Postgres database expires 30 days after it is created, and Render deletes it 14 days after that unless it is moved to a paid plan. That is the free plan. It is not a laptop, and it is not a tunnel. It is also not a database that stays online for years.

## Environment variables

### Render (API)

| Name | Required | What to put |
| --- | --- | --- |
| `DATABASE_URL` | yes | Provided by the Render Postgres database. `postgres://` is accepted. |
| `APP_SECRET_KEY` | yes | A random string of at least 32 characters. Not the word CHANGE_ME. |
| `APP_ENV` | yes | `production` |
| `COOKIE_SECURE` | yes | `true` |
| `COOKIE_SAMESITE` | yes | `none` |
| `TRUST_PROXY` | yes | `true` |
| `SEED_DEV_DATA` | yes | `false` |
| `FRONTEND_ORIGIN` | yes | The Netlify URL, for example `https://kpra-attendance.netlify.app` |
| `ALLOWED_ORIGINS` | yes | The same Netlify URL. Add a second origin with a comma if you use another hostname. |
| `BOOTSTRAP_ADMIN_EMAIL` | first boot | Administrator email. Remove after the account exists if you prefer. |
| `BOOTSTRAP_ADMIN_PASSWORD` | first boot | First password, 12+ characters, with a letter and a number. The first sign-in asks for a new password and an authenticator code. |
| `BOOTSTRAP_ADMIN_NAME` | no | Display name. |
| `TIMENEX_PORTAL_URL` | yes | `https://www.timenex.net:8443` |
| `TIMENEX_PORTAL_ENABLED` | yes | `true` when the portal login should be used. |
| `TIMENEX_USERNAME` | yes for push | TimeNex portal username. |
| `TIMENEX_PASSWORD` | yes for push | TimeNex portal password. |
| `TIMENEX_INTEGRATION_ENABLED` | yes | `false`. This switch does not send attendance. |
| `TIMENEX_WRITE_MODE` | yes | `none` |
| `SENSEFACE_ADMS_ENABLED` | yes | `false` |
| `PORT` | no | Render sets this. The process listens on it. |

`GET /health` does not touch the database. `GET /api/health` does.

The release command is the start command. `python -m app.entrypoint api` runs `alembic upgrade head`, then creates the bootstrap administrator if that email is not already in the database, then starts the API.

### Netlify (site)

| Name | Required | What to put |
| --- | --- | --- |
| `NEXT_PUBLIC_API_URL` | yes | Render API origin, no trailing slash. Example: `https://kpra-attendance-api.onrender.com` |

Set this before the build. Next.js bakes it into the browser code.

### This computer

Copy `.env.example` to `.env` as you already have. Do not set `APP_ENV=production` locally. Do not put the Render or Netlify tokens in `.env` or in git.

## Render

1. Sign in at [dashboard.render.com](https://dashboard.render.com).
2. **New → Blueprint**. Connect the Git repository that contains `render.yaml`.
3. Apply the blueprint. Service name `kpra-attendance-api`. Database name `kpra-attendance-db`. Region Singapore.
4. If the free database plan is refused, create the database on the lowest plan Render offers and set `DATABASE_URL` on the web service to that database’s internal connection string.
5. Open the web service → **Environment** and set every secret in the table above. `APP_SECRET_KEY` can be generated by the blueprint.
6. Save. Render restarts and runs migrations.
7. Open `https://kpra-attendance-api.onrender.com/health`. The body is `{"status":"ok"}`.

There is no Git remote in this folder yet. Render’s blueprint needs the files on GitHub, GitLab, or Bitbucket. The Netlify CLI can upload the site from this PC without that.

## Netlify

1. Sign in at [app.netlify.com](https://app.netlify.com).
2. **Add new site → Import an existing project**, or use the CLI from `frontend`:

```powershell
netlify sites:create --name kpra-attendance
$env:NEXT_PUBLIC_API_URL = "https://kpra-attendance-api.onrender.com"
netlify deploy --build --prod
```

3. Site settings → **Environment variables** → `NEXT_PUBLIC_API_URL` = the Render origin.
4. Trigger a new deploy after the variable is set. The public URL is `https://kpra-attendance.netlify.app` unless that name is taken.
5. Copy that URL into Render as `FRONTEND_ORIGIN` and `ALLOWED_ORIGINS`, then wait for the API to restart.

## Phone, passkeys, TimeNex

1. On the phone, open the Netlify URL. It is HTTPS.
2. Android: the browser can show **Install app**. iPhone: Safari → Share → **Add to Home Screen**. The icon opens without the address bar.
3. Sign in with the bootstrap email and password. Set a new password, then the authenticator code. Save the recovery codes.
4. Open **Account** and add this phone’s fingerprint or face. The passkey belongs to the Netlify hostname. A passkey made on localhost does not move here.
5. **Check-In** and **Check-Out** use the server clock. One biometric prompt is used when the policy requires a passkey.
6. **Mark attendance** is for an administrator. The TimeNex box stays off until it is ticked. A successful push says **Day replaced in TimeNex**. The punch remains a remote or administrator mark, not a terminal fingerprint.

A new database has no employees and no TimeNex links. Add the person and a verified TimeNex employee id in Administration before a push can succeed. Do not send a trial overwrite for a day that already exists in TimeNex.

## What stays on localhost

```powershell
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8010
```

```powershell
cd frontend
$env:API_PROXY_TARGET = "http://127.0.0.1:8010"
npm run dev
```

Leave `NEXT_PUBLIC_API_URL` unset for that. Passkeys on the PC still use `http://localhost:3000`.
